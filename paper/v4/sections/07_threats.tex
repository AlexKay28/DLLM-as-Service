\section{Threats to validity}
\label{sec:threats}

All measurements are on one GPU; the fitted constants are A100-specific
but the shapes should transfer. The crossover is calibrated at a
reference prompt of $\sim$\refPrompt\,tokens and shifts with input
length.

\paragraph{AR-30B arm: corrected and re-measured.}

An earlier draft of this paper reported AR-30B numbers from a harness
that differed from every other arm in three ways at once, all three
slowing the AR side. First, engine version: every DG, AR-3B and AR-1.5B
cell ran on vLLM 0.25.1 (torch 2.11.0, CUDA 13.0), but the AR-30B ran
on vLLM 0.11.0 (torch 2.8.0, CUDA 12.8). Second, CUDA graphs: the
AR-30B harness set \texttt{enforce\_eager}, which the anchor harnesses
don't, so the AR-30B decoded without graph capture. Third, and most
seriously, the AR-30B harness read its inputs from the gold record file
instead of the raw log file: the model was prompted with the answer it
was supposed to extract, which is why its 9-field F1 was exactly $1.0$
in every cell and its outputs were near-copies of the gold. The harness
has been corrected (raw input, graphs on, the paper's 9-field subset,
serial per-event timing, a provenance block, and a guard in
\texttt{build\_chat\_messages} that rejects any input that parses as a
gold JSON record) and all four AR-30B artifacts have been re-measured
on the pinned stack. The corrected AR-30B decodes at
\arSlope\,ms/token, close to the dense AR-3B's 6.3\,ms/token, which is
plausible for a MoE with the same active parameter count. The cost law
(Eq.~\ref{eq:ar}), Table~\ref{tab:niche}, the headline figures, the
batching multiplier and the cost-per-event table now all carry
provenance blocks verified by \texttt{paper/verify\_numbers.py}. This
is the same class of defect as correction~2 in
Appendix~\ref{app:defects}, a harness asymmetry flattering the
architecture we hoped would win, found, as those eight were, by
re-reading committed artifacts. Correction~9 in
Appendix~\ref{app:defects} prices the impact.

The AR--DG quality difference is equivalent at a $\pm 0.015$ margin
($\Delta = \qualityGap$, 95\% CI $[-0.012, +0.011]$, $n = 300$).
This is looser than the $\pm 0.010$ we pre-registered. At that
tighter margin the 95\% CI doesn't fit; equivalence holds only on
the 90\% CI.

This quality comparison uses the dense AR-3B baseline, not the AR-30B
MoE. The AR-30B's own 9-field F1 is 0.870, slightly above the dense
AR-3B's \arThreeBFnine, as expected for a larger model. The latency
comparison uses the AR-30B MoE cost law, so the quality and latency
arms are not the same model.

Several secondary results come from arms other than the MoE-matched
pair, and we flag them together not only at each use. The
per-event tail statistics (CV, max/median) in Table~\ref{tab:summary}
and Table~\ref{tab:contrast} are the dense AR-3B; the AR-30B was never
run per-event. The BGL$\to$HDFS generalisation was measured on the
dense AR-3B for the AR side. The perturbation, refinement and
bounded-deadline probes in Appendix~\ref{app:refuted} were run on
\LLaDA, a second diffusion model, against the dense AR-3B. And the
serial headline is a batch-1 result: the same AR-30B batches
$25\times$, so a deployment that can batch inverts the economics
entirely (\S\ref{sec:limits}).

The surviving niche has not been tested on a task whose natural output
length is $\geq 512$ tokens. The AR-30B cost law is fitted from a
five-point serial sweep with $R^2 = 0.9996$, but the model stops at
$\sim$126 tokens (EOS), so the slope is carried by the $L{=}32$ point
and the cluster at natural output. The advantage in serial is the
realized comparison; forcing AR to generate longer output would
increase its latency per the cost law, making DG's advantage larger.
Appendix~\ref{app:forced} works that projection through a multi-record
task whose natural output is long.

The niche has not been tested against grammar-constrained AR decoding,
which would eliminate over-generation, guarantee 100\% schema
validity, and remove the diffusion model's completeness advantage. An
attempt to run grammar-constrained decoding on the dense AR-1.5B
(vLLM 0.10.2, using the outlines~\cite{outlines2024} backend) produced
1.0\% schema-valid output, the grammar enforced JSON structure but
the model padded string fields it could not answer, preventing the JSON
from closing. That is one model on one older engine, so it bounds
nothing; the comparison against a properly tuned grammar-constrained
AR remains untested.

The batching ceiling reproduces across two runtimes and two model
families, DG on vLLM and \LLaDA\ on dInfer, but both measurements
are engine-bounded; see
Appendix~\ref{app:batching}. A structural argument for why the ceiling
is likely architectural is in Appendix~\ref{app:batching_architectural}.

The cost-shape generalisation is inferred from one block-diffusion
model measured against one AR family. The shape claim is structural but
not tested on a second diffusion family.

The energy comparison uses three different idle baselines (49.7\,W for
AR-30B, 52.6\,W for DG, 58.6\,W for AR-1.5B); both the AR-30B and DG
energy runs are now serial, but the DG energy was not re-measured at
the AR-30B idle point, so the ratio is indicative instead of directly
controlled.
